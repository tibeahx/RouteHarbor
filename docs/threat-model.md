# Модель угроз

Активы: трафик LAN, DNS-метаданные, ключи API/VPN/Wi-Fi, настройки сети и доступ
к управлению. LAN, импортированные данные, ответы внешних серверов, обнаруженные
узлы и скачанные пакеты недоверенны. Обнаружение устройства не разрешает управление.

| Граница | Контроль | Проверка |
| --- | --- | --- |
| Браузер → API | Bearer, Host/Origin allowlist, CSP, отсутствие CORS и query-токенов | auth, CSRF, rebinding, XSS |
| Read-only → запись/секреты | отдельная роль и проверка каждой операции | ACL tests |
| Импорт → движок | строгий allowlist, размеры/глубина, запрет listener/file/script | malicious fixtures, fuzz |
| Проба → сеть | HTTPS, закрепление проверенного IP, запрет private/link-local и redirects | SSRF tests |
| API → root helper | Unix socket, peer credentials, типизированные операции, повторная проверка | helper tests |
| Применение → сеть | собственные таблицы, журнал, независимый watchdog, fail-closed | Linux crash/rollback lab |
| Обнаружение → узел | подтверждённый fingerprint, одноразовая привязка, уникальная идентичность | pairing tests |
| Release → устройство | подпись manifest, доверенный ключ вне архива, hash/arch/version/commit | tamper tests |

Секреты не входят в обычные ответы, события, ошибки, аргументы процессов и
диагностику. Конфигурация имеет права 0600, каталог 0700, запись атомарная с fsync.
История и очереди ограничены, измерения не пишутся постоянно во flash. Нет облачной
телеметрии, TLS MITM, универсального пароля, скрытого recovery-ключа или shell API.

Физическое владение роутером, компрометация ядра и root за пределами контроллера
не устраняются этими мерами. Проверки TCP/UDP/DNS/IPv6 при boot/crash/update и
радиосовместимости обязательны для допуска конкретной платформы к стабильному
релизу. Наличие кода или unit-тестов не является подтверждением этих свойств.

Опциональный private relay становится доверенной точкой выхода: владелец relay
может видеть назначения, метаданные и незашифрованный прикладной трафик. TLS между
worker и relay с взаимно закреплёнными SHA256 fingerprint защищает транспорт и
исключает непрошенное подключение другого клиента. Собственная identity хранится
отдельно от публичной конфигурации; её private key не попадает в API, диагностику,
аргументы процесса или журнал. Адрес relay задаётся явно числовым public IP:port.

Frames, очереди, число flows и disconnected grace ограничены; старые/лишние UDP
датаграммы отбрасываются и учитываются счётчиками. Отказ аутентификации, worker или
relay не разрешает прямой обход для bypass-класса. Включённый continuity несовместим с direct fallback
и break_existing. Наличие hot standby не устраняет общий отказ WAN или VPS и не
является доказательством физической задержки переключения.

Selective routing явно разрешает аварийный direct при отказе диспетчера или его
DNS: это выбор доступности, при котором ранее обходившиеся назначения могут
обратиться через WAN. Разрешение хранится в подтверждённом журнале и не отменяет
maintenance hold. Watchdog снимает только объекты RouteHarbor; FakeIP не выпускается
во внешнюю сеть. Обновления списков и detector не получают такого разрешения.

Домены из списков и DNS-наблюдения недоверенны. Загрузчик ограничивает объём,
проверяет публичные закреплённые адреса и формат, затем публикует снимок атомарно.
Детектор проверяет одинаковые public IP/SNI/certificate по direct и фактическому
обходу; не повторяет пользовательские запросы, не расширяет правило на общий CDN.
Сырые DNS-наблюдения остаются в ограниченной памяти. HTTPS/SVCB ответы без данных
снижают обход FakeIP через address hints; собственный DoH приложения и строгая
DNSSEC-валидация синтетических ответов остаются ограничениями модели.
