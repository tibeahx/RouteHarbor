# Implementation security review

Review date: 2026-09-08. Scope: source import and engine generation, independent probes, API authentication and mutation boundaries, configuration reload and transaction coordination, startup recovery, packet-process supervision, paired gateway/node Wi-Fi coordination, and release-manifest verification. A collaborating implementation agent reviewed the API/control/auth code independently of its original author. This is a source and regression-test review, not an external security audit or physical-router certification.

## Verified findings and corrections

| Finding | Correction and evidence |
| --- | --- |
| A running authentication store could ignore local CLI revocation or overwrite credentials issued by another process. | Every operation reloads the authoritative private file while holding a bounded process lock. File ownership, regular-file type, permissions, symlinks and hardlinks are checked. `internal/auth/auth_test.go` exercises live-store issuance/revocation and hostile files. Token-file reading uses one bounded, no-follow descriptor. |
| A new inactive source with a missing engine blocked preparation of healthy routing paths. | New uncommitted failures are explicitly partitioned into unavailable IDs; the private checkpoint still includes every enabled source. Compiler tests reject overlap, omissions, duplicates and unavailable selection. Committed transparent inputs retain their strict engine ownership requirement. |
| A completed engine process remained attached to its adapter and prevented recovery. | Waiters clear only their own process generation. Startup waits for the allocated listeners. Real subprocess tests cover exit before readiness, recovery on the same ports/mark, and reconfiguration concurrent with startup. Pinned sing-box and Xray also pass actual native restart tests. |
| Controller restart could allocate different ports/marks than the helper's committed routing intent. | Private transaction checkpoints are written before apply. Startup matches the committed intent to private source settings and restores its original allocations; collisions fail without touching unrelated listeners. Removed sources retain their private configuration until confirmation releases rollback dependencies. Tests cover port collisions, staged removal, missing checkpoints, and the confirm/promotion crash window. |
| Source or network edits could invalidate a pending transaction or an active rollback endpoint. | Pending transactions lock configuration edits. Active endpoint/DNS/IPv6/interface changes require removing and confirming those paths first. Revision changes cancel old probes and reject stale measurements. Network disable with committed policy directs the operator to explicit trusted-local decommission. |
| A partial closed-to-direct apply or guarded-direct rollback could lose the prior safety ownership. | Rollback uses a trusted internal union of previous and candidate guard coverage. Actual Linux regression tests cover both guarded and unguarded starting conditions and preserve the prior protected interfaces. |
| A guarded network could be presented as applied, and selecting the same source could leave it guarded. | Status exposes the guard; reconciliation reapplies even an unchanged selection after an independent guard. Focused coordinator tests cover both conditions. |
| A first direct/interface source probe required a network transaction before it could be checked. | Typed native-path registration now prepares marked probe sockets without mutating routes or nftables. Slot collision checks include packet, native, committed and pending paths; actual tunnel identity is checked at registration and dial. Linux RPC tests use direct and GRE paths to isolated public-IP fixture addresses, verify received socket marks and source interfaces, and confirm unregister removes access. |
| Target DNS could leave through the gateway resolver while protected source paths were being measured. | Managed probes use the explicit numeric resolver through each candidate's TCP path. No resolver means hostname probes fail with an explicit code; there is no system fallback. DNS wire-format tests return different answers over distinct source paths and verify that a poisoned global resolver is unused. Startup restores the committed helper DNS policy instead of a potentially edited offline draft; coordinator regressions reject draft attempts to disable or replace that live policy. |
| Root-only native startup tests concealed missing TPROXY permissions under the packaged service user. | The failure was reproduced under UID/GID 65534. A typed helper now regenerates and validates each strict engine configuration, passes it through a root-owned read-only inherited descriptor, and launches the engine as the actual API peer UID/GID with only `CAP_NET_RAW`. Native worker tests prove the API has zero capabilities, the engine has only the required capability, listener inodes belong to the child, and API/helper death releases the child and ports. No global file capability is added. |
| Helper death could leave nfqws alive after its credential change cleared the kernel parent-death signal. | A fixed root worker owns nfqws and observes a private manager-liveness pipe. EOF terminates and reaps the child. A readiness handshake requires the exact queue to be bound to that child PID. Native Linux tests kill the manager and verify that the dropped-privilege child disappears. |
| Public-address policy could diverge between the unprivileged probe and privileged dial/DNS sinks. | They now share `platform.PublicAddress`, including mapped-local, translated, documentation, reserved and deprecated site-local ranges. Numeric destinations remain pinned through SOCKS/CONNECT while TLS verifies the original hostname. |
| Separate gateway/node confirmations could leave an already committed node behind an expired gateway rollback timer. | The durable coordinator confirms the gateway first while retaining its compensation snapshot, confirms the node, then finalizes the gateway. Response-loss and restart tests prove reconciliation; a node watchdog rollback triggers gateway compensation. The protocol explicitly reports that this is not an atomic distributed commit. |
| Participant IDs or rollback during uncertain confirmation could bypass paired ordering and remove backhaul behind a committed node. | Public mutations require the aggregate transaction ID. The confirming phase must reconcile before manual rollback. Pinned TLS tests exercise participant-ID rejection, lost node confirmation, lost gateway finalization, and recovery without rolling back the committed pair. |
| Generic wireless support or a receipt for another peer could enable the wrong Wi-Fi pair. | Managed plans require reciprocal gateway/node fingerprints, matching receipt modes and the node's verified radio. Apply and initial confirmation recheck current evidence. Tests reject wrong/missing peer, radio and mode metadata and prove revocation blocks both participants before mutation. Privileged gateway eligibility independently binds its adopted AP to the receipt's actual radio. |
| Private gateway AP credentials could escape through paired previews, helper responses or completed coordinator state. | Only the typed private Wi-Fi payload crosses authenticated helper and pinned node TLS channels. Public results explicitly copy redacted participant summaries. Tests use a secret canary and verify it is absent from previews and preparation responses, and erased from the coordinator journal after confirmation. |

Strict imports reject unknown/duplicate keys, arbitrary listeners, routes, files, scripts, marks, executable paths and helper arguments. Authentication, Host/Origin restrictions, read-only ACLs, explicit secret export, request bounds, journal idempotency and redacted ordinary outputs were inspected and exercised by the API/auth suites. Release verification checks the detached Ed25519 signature before interpreting manifest content, then exact artifact name, architecture, stable-version downgrade policy, size, inode identity and SHA-256. Its trust key must come from the operator's independent trust channel.

## Executed evidence

- `go test -race ./...` passed across the repository. Focused adapter/probe/control/config/auth/API race suites also passed after their review fixes.
- `scripts/lab-engines.sh` initially passed as container root with pinned sing-box 1.14.0 and Xray 26.3.27: six native configuration validators; actual IPv4/IPv6 TCP/DNS input startup; forced process death and restart with unchanged allocations; controller SIGKILL and successful restoration of committed ports.
- `scripts/lab-paths.sh` passed real direct, two independent nfqws profiles and CONNECT traffic isolation. The run completed 32 concurrent requests; killing one profile failed that path closed while the other three paths remained available.
- `scripts/lab-engine-worker.sh` passed actual service-user sing-box/Xray capability checks, unprivileged API RPC startup and ordinary-RPC admission, API/helper SIGKILL cleanup, and restored-port startup/explicit-stop checks.
- `scripts/lab-network.sh` covers actual nftables/routing ownership, rollback guards, independent watchdog recovery and packet-worker cleanup in the disposable Linux container. Its packet tests use the pinned nfqws binary, not a replacement packet processor.
- `go test -race ./internal/node -run TestCoverage` passed the paired coordinator suite after the final review fixes. The node participant uses the real pinned loopback TLS protocol and durable node transaction manager; the gateway and UCI effects are injected fixtures. These tests do not establish physical WDS/mesh compatibility.
- `scripts/lab-openwrt.py` passed ordinary SDK-IPK installation and service lifecycle with actual OpenWrt opkg/procd/netifd/fw4 userland, unprivileged controller/node identities, protected apply/confirm, restart/reload and explicit decommission/removal. See [SDK evidence](evidence/openwrt-sdk.md). It runs under the Docker Linux kernel with dummy interfaces and does not test full OpenWrt boot or physical radios.

The Linux laboratories use disposable containers with no external network during tests. They do not join the host network. Test-binary mounts are read-only; namespace and privileged network mutations stay inside the Docker Linux VM.

## Remaining acceptance boundaries

These results do not establish ISP-specific censorship bypass, safe flashing of a particular router, full OpenWrt device boot and reload ordering, wireless backhaul performance, or physical multi-device failover. The SDK/package lab separately exercises actual OpenWrt procd/netifd/fw4 userland in a container; it does not boot router hardware. Device-specific checks remain release gates in the project acceptance documentation. The engine import surface intentionally supports its documented strict subset; unsupported transports and capabilities fail explicitly. Endpoint-hostname bootstrap uses the existing resolver before engine startup; deployments needing to avoid that disclosure must configure a numeric server and explicit TLS identity. No external resolver or traffic destination is silently added.
